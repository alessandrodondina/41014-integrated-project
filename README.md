# 41014 Sensors and Control — Integrated Project

## Project Overview

This project implements an autonomous mobile robot navigation and docking system in MuJoCo, using a simulated TurtleBot3-style differential-drive robot.

The robot navigates through an environment containing obstacles, uses wheel odometry and an Extended Kalman Filter (EKF) for localisation, monitors its surroundings with a simulated 2D LiDAR, and uses an onboard camera to detect an ArUco marker at a charging station.

The system integrates navigation, sensing, localisation and feedback control into a complete autonomous docking demonstration.

## Software and Technologies

- Python 3.11
- MuJoCo 3.17.0
- NumPy
- Matplotlib
- OpenCV with ArUco support

## System Components

### 1. MuJoCo Simulation

The simulation includes a TurtleBot3-style mobile robot, walls, three obstacles, a charging station and an ArUco landmark.

The robot uses a simplified kinematic differential-drive model. Wheel speeds are converted into changes in robot position and orientation. The simulation is not intended to reproduce full motor torque, friction or wheel-slip dynamics.

### 2. LiDAR

A simulated 2D LiDAR uses 36 rangefinder measurements distributed around the robot.

LiDAR measurements are used to monitor nearby obstacles and stop forward movement when an obstacle is within a specified safety threshold.

### 3. Camera and ArUco Detection

The onboard RGB camera detects an ArUco marker mounted at the charging station.

Camera intrinsics are calculated from the simulated camera's field of view. Marker measurements are used to estimate distance and bearing.

Camera detection and distance estimation were tested against known positions in the simulation.

### 4. Extended Kalman Filter

The EKF estimates the robot's planar state:

[x, y, heading]

Prediction uses differential-drive wheel odometry.

Correction uses range and bearing measurements from the known ArUco landmark.

The filter maintains a covariance matrix representing localisation uncertainty.

### 5. Autonomous Navigation

The robot follows a sequence of six waypoints through the simulated environment.

A proportional feedback controller adjusts forward velocity and angular velocity using the estimated robot pose.

LiDAR monitors nearby obstacles during navigation.

The route is predefined rather than generated by a global path-planning algorithm.

### 6. Camera-Guided Docking

After reaching the final navigation waypoint, the robot aligns towards the charging station.

The camera detects the ArUco marker and estimates its distance and bearing.

A proportional docking controller adjusts the robot's movement until it reaches the specified stopping distance.

The system stops if camera tracking is lost or a LiDAR safety threshold is exceeded.

Docking represents a visual approach to the station, not physical electrical charging.

## Installation

Create and activate a Python virtual environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Run commands from the project root directory.

## Running the Project

Run the complete autonomous demonstration:

```bash
python tests/test_integrated_project.py
```

Run the individual tests:

```bash
python tests/test_ekf_mujoco.py
python tests/test_ekf_camera.py
python tests/test_waypoint_navigation.py
python tests/test_docking.py
```

## Integrated Demonstration Results

The successful integrated test produced:

| Measurement | Result |
|---|---|
| Navigation waypoints | 6 / 6 |
| Camera marker detections | 341 |
| LiDAR safety-stop activations | 0 |
| Final robot position | (1.328, 1.755) m |
| Final distance to station marker | 0.574 m |
| Docking status | DOCKED |

The docking target was approximately 0.55 m from the station marker. The final simulated distance was 0.574 m, corresponding to an absolute difference of 0.024 m.

The successful route did not trigger the LiDAR safety stop. This demonstrates monitoring during the run, but does not independently validate the safety-stop response under a deliberately introduced obstacle.

## Limitations

- The robot uses kinematic rather than full dynamic wheel control.
- Navigation follows predefined waypoints.
- LiDAR provides safety monitoring rather than global path planning.
- Camera measurements depend on marker visibility and image geometry.
- The simulated docking target does not include physical charging contacts.
- Additional testing would be required to establish performance under sensor noise, unexpected obstacles and varying initial conditions.
